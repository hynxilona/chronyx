Contribute

Bring code.
Leave the balances alone.

Every change is reviewed, and every change is checked by a machine before a person reads it. A pull request that could create quanta, move someone's balance, or slip a binary into the tree does not merge — not with a good explanation, not with a green test run.

01

How a change gets in

Five steps. None of them can be skipped, including by the maintainer.

  1. Propose it as an issue

    Describe the problem before the patch. Consensus, balance and supply changes say so in the first line, because those get a design note before anyone writes code.

  2. Open one scoped PR

    One idea per PR. A diff a reviewer can hold in their head gets read properly; a 2,000-line PR gets skimmed, and skimming is how bugs land.

  3. Pass the machines

    Format, clippy, tests, the supply guard, the invariant suite, the secret scan, the dependency audit, and a binary-file check. The full list is below.

  4. Get a human

    CODEOWNERS covers genesis, state, blocks, PoH, PoA, PoW, the ledger and the release workflows. Those files need the maintainer to read them and write down why balances cannot move.

  5. Merge, squash, keep the reason

    The commit message keeps the why. The issue keeps the argument. Six months later that is the only thing that explains the code.

02

What the checks stop

Each one exists because a specific class of accident is possible.

CheckWhat it catches
cargo fmt · clippy -D warningsunreadable diffs, dead code, sloppy error handling
cargo test --workspaceconsensus and ledger regressions
scripts/guard-supply.shany new path that creates quanta, moved supply constants
invariants.rsa transfer that mints, a genesis above the cap
check-pr-files.shbinary blobs, droppers, 800-line surprise diffs
gitleakskeys and tokens committed by accident
cargo auditdependencies with known vulnerabilities

The threat model is boring on purpose. The realistic attack on a chain this young is not a clever cryptographic break — it is a friendly PR that quietly adds one line to the account state. So that is what the pipeline is built to make impossible to miss.

03

Rejected on sight

Not "needs discussion". Rejected.

  • Anything that creates quanta outside genesis and transfer credit
  • A supply constant change without a public proposal
  • Binary files, archives or minified blobs in a diff
  • unsafe without the invariant it upholds
  • Network or filesystem I/O inside chronyx-core
  • Obfuscated identifiers or encoded strings
  • Telemetry of any kind, in the node or the CLI
  • "Temporary" debug paths that ship
