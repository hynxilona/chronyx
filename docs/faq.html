FAQ

The questions
you should ask.

If a stranger sent you this link, these are the things worth checking before you believe anything else on the site. Short answers, including the ones that are not flattering.

01

The chain

What it is, and what it deliberately is not.

Is this a real blockchain, or a wrapper around something else?

A real one in the narrow sense: its own state machine, its own peer-to-peer protocol, its own append-only ledger, and native accounts. There is no EVM, no contract VM, and no token contract. Run chronyx devnet join and your node downloads and replays every block from genesis — if the rules were wrong, the state would diverge and you would see it.

Why Proof of Authority? That is just a permissioned chain.

Correct — at v1 it is permissioned. Four keys defined in genesis take slots in turn, and three of them must sign. That is a deliberate devnet choice: 400 ms deterministic finality, and a failure surface small enough to reason about.

PoW is the exit from that. A proof of work is how a new validator earns a slot, so entry costs compute rather than a token or an allowlist. The mining and verification code exists today; wiring a proof into a scheduled slot is the next milestone, not a shipped feature. The site says so on every page that mentions it.

Why not fork Solana or use an existing framework?

Because the interesting parts are exactly the ones a fork hides. PoH here is a sequential SHA-256 chain — 50 ms per tick — not Turbine, not Gulf Stream. The ledger is JSONL replayed at startup, gossip is plain TCP, and accounts are Ed25519 with per-account nonces.

It is smaller than Solana on purpose. Every line is meant to be readable by one person in an afternoon.

What does 400 ms finality actually mean?

Slots are 400 ms. The scheduled leader for a slot produces one signed block; three of the four validators sign it; the block is final in that slot. There is no probabilistic waiting and no reorg window. If quorum is not reached, the slot is empty and the chain moves on.

How fast is it? What is the TPS?

Unknown, and no number will be quoted that cannot be reproduced. The block interval is fixed at 400 ms. Transactions per block is a different question, and there is no benchmark command or public node to run one against yet. When there is, the command will be in the repo next to the result.

02

Supply and money

The part where most projects start lying.

Can I buy CHRONYX?

No. There is no sale, no presale, no market, and no listing. Devnet coins come from a faucet and are test units. Any account, site or person offering to sell you CHRONYX is scamming you.

If a market ever exists it will be after an audit and a mainnet, and it will be announced in the repo first.

How do I know the supply is really fixed?

Genesis creates exactly 600,000,000 CHRONYX, and every transfer conserves quanta. Four invariant tests cover the genesis cap, conservation across transfers, rejected transactions changing nothing, and the absence of a mint path. A source guard fails CI if quanta are created outside state.rs or the supply constants move, and branch protection requires those checks before a merge.

The honest limit: this is tests and a guard, not a formal proof. That is precisely what an external audit is for.

Is there an airdrop or a token sale planned?

No airdrop, no sale, no points program. The mainnet split in TOKENOMICS.md is a plan for where the same 600M would sit — community, bootstrap validators, treasury, team, liquidity — and none of it is implemented in v1. Genesis only knows flat public-key balances.

Where is the audit?

Not done, not booked. An external consensus and state-transition review is the first thing funding goes to; the working estimate is $25k–60k, which is more than this project has. Until it happens, treat the code as unaudited and do not put value on it.

The costs and the spending rule are public in docs/FUNDING.md.

What happens to devnet coins if the chain resets?

They disappear, because a reset ships a new genesis and a new chain id. Every reset is announced in the repo first, with the old genesis hash and the new one, so nobody is surprised. Devnet balances are not an investment and not a promise.

03

People and risk

Who is accountable, and what happens when they are not here.

Who is behind this?

One independent developer. No company, no foundation, no investors, no team page with stock photos. That is a real risk and it is stated plainly rather than dressed up.

The mitigations are structural: MIT license, no admin key, no mint function, and a ledger anyone can replay from genesis.

What happens if you disappear?

The code keeps working. Binaries and source are public under MIT, the ledger is append-only and replays from genesis, and there is no admin RPC or mint key to lose. Anyone can fork it or keep running the existing chain.

What does not survive is the roadmap, the audit funding, and the person answering issues. Judge the project on the code, not on me.

Can I run a validator?

Anyone can run a follower today: two commands, no application. Signing slots are four, fixed in genesis, and handed out by hand for this devnet. Applications are queued for the next reset, and everyone in the queue is pinged before it happens.

The milestone that removes the manual step is PoW admission. See the validator guide.

Is this a scam?

A scam needs something to take. There is no sale, no deposit address, no token to buy, and no wallet connection on this site. The faucet gives away test coins that are worth nothing.

If someone claiming to represent Chronyx asks you for money or a seed phrase, they are lying.

Still unanswered? Open an issue with question: in the title and the answer gets added here.

PoH orders. PoA finalizes. PoW admits. A Rust chain with a fixed supply and no framework to hide behind.
