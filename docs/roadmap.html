Roadmap

What exists,
and what doesn't.

Ordered by dependency, not by date. An item moves to Shipped only when it is on main and a stranger can run it. Anything not listed under Shipped does not exist yet, whatever a post may imply.

01

Shipped

On main, in the release binaries, and covered by tests.

PieceWhat works today
Chain coreState, blocks, genesis, deterministic replay from the first block.
PoH50 ms SHA-256 ticks; two nodes that agree on the hash agree on the order.
PoA400 ms slots, round-robin leaders, 4 validators, quorum 3.
PoWMine and verify hashcash-style proofs. Admission is not wired yet.
AccountsEd25519 keys, per-account nonces, signed transfers.
LedgerAppend-only blocks.jsonl, replayed at startup; state is rebuilt, not stored.
GossipPlain TCP: hello and height, GetBlocks catch-up, live block fan-out.
Interface15 HTTP RPC routes and about 50 namespaced CLI commands.
Supply guard4 invariant tests, a source guard, and branch protection on the files that decide a balance.
Tests35 passing; fmt clean and clippy -D warnings clean.
ReleaseBinaries for Linux, macOS and Windows with one checksum file for all of them.
SiteThese pages. Static, no tracking, no analytics.
02

Next, in order

Each step unblocks the one after it. None of them is a promise of a date.

  1. PoW admission

    A valid proof becomes a scheduled slot. Mining and verification already exist in core; what is missing is the state transition that admits the key and the epoch logic around it. This is the change that lets the validator set grow without a human deciding who joins.

  2. A public seed node

    A stable host others can join, plus a status snapshot generated from it. A devnet nobody can reach is a local test with extra steps.

  3. A read-only explorer

    Blocks, accounts and supply read straight from RPC. No wallet, no signing, no token — just a way to check the chain without installing it.

  4. An external audit

    Consensus and state-transition review by a firm that does this for a living. It needs funding first; the budget and the public spend rule are in docs/FUNDING.md.

  5. Fix, then audit again

    Findings fixed and reviewed a second time. One audit is an opinion. Two is a process.

  6. A devnet reset with outside operators

    Six to eight validators, at least four outside one timezone. The current four slots are full and were never meant to be permanent.

  7. Mainnet

    Only after the audits and a testnet that has survived real operators. There is no date here, and none will be invented to make a post look better.

03

Not in v1

Listed so nobody has to guess whether it is coming next week.

Not shippingWhy
Token sale, presale, airdropNothing to sell. Devnet coins are free test units.
Staking rewards or inflationThe supply is fixed. Validator incentives are a mainnet design question.
EVM or smart contractsNative transfers only. There is no VM and no plan to bolt one on for v1.
On-chain governanceMultisig and process come after the audits, not before.
Light clients or a mobile walletNot started. The RPC is the interface for now.
Exchange listingsNot applicable. There is no market and no token to list.
04

How this list is maintained

The rule is boring on purpose.

Shippedneeds proof

A merged commit and a command a stranger can run. If it only exists in a branch or a screenshot, it is not shipped.

Nextneeds code

Either something in the tree or a written design in docs/. Ideas without either stay out of the list.

Datesstay out

An order is useful; a date is a guess that turns into a lie when one thing slips. When something is scheduled, the commit says so.

Check it yourself. The commit history is the only changelog: github.com/hynxilona/chronyx/commits/main.

PoH orders. PoA finalizes. PoW admits. A Rust chain with a fixed supply and no framework to hide behind.
